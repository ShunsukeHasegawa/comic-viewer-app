# /code-review の指摘を直す

## 1. 指摘を集める

- この会話に直前の `/code-review` の結果があれば、それを使う。
- 無ければ `code-review` スキルを実行して指摘を出す（`--fix` は使わない。ここで一件ずつ判断する）。

## 2. 一件ずつ確かめる

各指摘について、コードを読んで本当に起きるかを確かめ、次のどれかに分ける。

- **直す**: 起きる。
- **直さない**: 起きない / CLAUDE.md で意図して決めたこと（例: 「作らない」と決めた機能、
  ログイン / 復元を止めない判断）。理由を一行で残す。
- **ユーザーに聞く**: 直し方が仕様の判断になる（どちらの挙動が正しいか決められない）。

## 3. 直す

- 直すものには、**その指摘の状況を再現するテスト**を先に書き、直す前に落ちることを確かめる
  （テスト名は日本語で、何が起きてはいけないかを書く）。
- 直した結果、コードから読み取れない方針が増えたら CLAUDE.md の該当の節に足す。
- `conventions-reviewer` に差分を見せ、`/check` を通す。

## 4. コミット

- 1 行目は既存の形に合わせる:
  `fix: <直した内容の要約>（#$ARGUMENTS の /code-review 指摘）`
  （Issue 番号が無ければ `（/code-review 指摘）`）。同じ Issue で 2 回目以降なら
  `fix: レビュー指摘の修正 2 回目（#$ARGUMENTS ...）` のように回数を入れる。
- 本文に、直した指摘と直さなかった指摘（理由付き）を箇条書きで書く。

## 5. 報告

直した / 直さなかった / 聞きたいことを分けて短く報告する。
